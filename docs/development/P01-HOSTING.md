# P01 Render deployment

Prepared configuration, not an attestation of deployment. The repository remains public under the recorded owner exception; credentials stay in Render environment variables and ignored local files.

## Topology

The default Docker target, demo-host, runs the Next.js web server, loopback-only API and worker in one supervised synthetic host. Only the web port is public. Supabase provides PostgreSQL and OIDC. A child failure exits the host so Render can restart it. The web readiness endpoint checks the API's database/schema readiness. This small-demo topology avoids sending signed BFF identity over a public API endpoint. It is not the production scaling topology.

The existing explicit web/api/worker image targets remain available. render.yaml selects Singapore and a Standard compute plan; the account owner must review the displayed Render price before creating billable resources.

## Deployment procedure

1. Connect the authorized Render workspace to Jobo-Banta/lara. Create a Blueprint from render.yaml using the reviewed main commit. Automatic deploys are disabled.
2. Supply APP_BASE_URL with the actual generated HTTPS URL. Supply OIDC_REDIRECT_URI as that URL plus /auth/callback. Register that callback and the hosted /oauth/consent URL in the existing Supabase OAuth configuration as applicable; retain localhost callbacks needed during development.
3. Enter OIDC issuer/client ID/client secret, Supabase publishable key, DATABASE_URL for lara_api and WORKER_DATABASE_URL for lara_worker. Use the existing restricted TLS connection strings, including sslmode=verify-full or require. Never deploy the owner or migrator connection.
4. Render generates SESSION_SECRET. It must be identical for web and API; the single host shares it. SESSION_SECRET_REF=local-file is the current resolver's environment-backed engineering mode, not a committed secret file.
5. Apply reviewed migrations with the dedicated migrator from the operator environment before routing traffic. Provision each invited verified subject using scripts/provision-demo-subject.mjs. The host cannot grant itself demo entitlement.
6. Deploy, check /api/health/ready returns 200, and complete a real Supabase login on the hosted URL. Run the six task cards and verify isolated browser sessions. No real financial execution is enabled.
7. Record URL, source commit, Render deploy ID/image digest, schema 0008 or later, login evidence, browser evidence and usability observations. Only then tag and attest 0.1.0.

Rollback: redeploy the prior known-good image while preserving the additive schema. Do not reset Supabase or overwrite another session. Review compatibility before rolling back across a schema requirement.

## External requirements still needed

An authorized Render workspace with billing/region accepted, the actual hosted URL, Supabase hosted callback configuration, and eight representative participants. These cannot be generated by an automated test.
